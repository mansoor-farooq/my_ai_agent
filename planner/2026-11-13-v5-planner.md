## Status rules

- **Not started** — no implementation exists for this scoped V5 deliverable.
- **Planned** — scope and acceptance criteria are recorded; work has not begun.
- **In progress** — work has begun and the status entry names the active task.
- **Implemented, unverified** — code/package files exist, but required checks
  have not been observed passing for the recorded revision.
- **Verified** — required checks passed and their command/result/date/revision
  are recorded in `2026-11-13-v5-status.md` or the dated history file.
- **Blocked** — a concrete external dependency prevents progress; record it.
- **Superseded** — a newer approved design or release replaces this item.

File existence, an old test result, or a green local doctor alone never changes
an item to **Verified**. Do not mark a capability “sandboxed” unless runtime
probing proves which isolation boundary is active on that machine.

## How to keep this current

For each V5 change, update `2026-11-13-v5-status.md` in the same change as the implementation
and add a dated entry to `2026-11-13-v5-history.md`. Record the exact product/package
version, repository revision, changed capabilities, verification commands and
results, remaining gaps, and whether install/upgrade behavior was checked.
Keep unfinished tasks checked as `[ ]`; use `[x]` only after the acceptance
gate has evidence.
