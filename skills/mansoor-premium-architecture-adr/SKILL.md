# Premium architecture decisions

Write one focused decision record with context, forces, decision, consequences, alternatives, evidence, owner, date, and review trigger. Link it to the affected modules, contracts, tests, and rollout plan. Distinguish observed facts from estimates.

Prefer updating a superseded decision with a new record rather than rewriting history. Keep decisions small enough to revisit when constraints change.

Stop when implementation and verification can point back to an accepted decision record.
