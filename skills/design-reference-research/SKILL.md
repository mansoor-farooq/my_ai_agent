# Design Reference Research

Research the design principle behind a reference and adapt it to the user's product. The output is a short, traceable design decision—not a mood-board of uncited screenshots.

## Method

1. Inspect the product and write down the surface, audience, task, constraints and existing brand before searching.
2. Search current primary references first: official design-system documentation, product documentation and first-party examples. Use reputable secondary coverage only to fill a clearly stated gap.
3. Open the cited pages and verify each relevant claim in context. Record publisher, page title, direct link, access date and the specific transferable pattern. A search snippet alone is not evidence.
4. Compare at least two materially different directions when the brief leaves room. Explain usability, accessibility, performance, implementation cost and brand-fit trade-offs.
5. Extract principles and approximate tokens; do not copy a reference layout pixel-for-pixel, reproduce protected artwork, or present another company's asset as the user's.
6. Produce a compact recommendation and textual/wireframe blueprint. Include responsive and keyboard states. Ask the user only if a decision materially changes the product or they have not approved a direction.
7. If browsing is unavailable, say so, rely on local product evidence, and label remembered patterns as unverified. Never fabricate links, benchmarks or design-system rules.

## Research note format

| Reference | Verified pattern | Product adaptation | Trade-off / check |
|---|---|---|---|
| First-party page and direct URL | Only the observed interaction or design rule | What changes for this product | Contrast, responsive behavior, load cost, or maintenance |

Use current official design-system documentation for version-specific components. Use WCAG 2.2 as an accessibility reference and test the implemented interface instead of treating a cited guideline as proof of conformance.
