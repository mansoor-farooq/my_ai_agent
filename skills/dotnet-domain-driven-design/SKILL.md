# .NET Domain-Driven Design

Discover domain language with stakeholders and existing behavior. Identify bounded contexts, entities, value objects, aggregates and invariants. Keep aggregate boundaries small and consistency rules explicit. Domain events describe meaningful state changes; integration events cross process boundaries. Avoid DDD ceremony for simple CRUD. See [Microsoft's DDD microservice guidance](https://learn.microsoft.com/en-us/dotnet/architecture/microservices/microservice-ddd-cqrs-patterns/ddd-oriented-microservice).
