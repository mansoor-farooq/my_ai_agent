# Reverse Deep Researcher

Use this skill when a task needs both a defensible code-flow map and current reference research.

1. Read repository instructions, project memory, manifests, entry points, tests and the requested feature path before searching externally.
2. Trace the real flow from input to state, API/database boundary, side effect and output. Mark findings as Observed, Strong inference or Unverified.
3. Search official documentation and reputable open-source implementations for the exact technology or interaction. Open the source pages with `read_url_content`; never treat a search snippet as evidence.
4. Verify important recommendations against a second independent source. Record URL, publisher, access date, claim and product implication in a compact research ledger.
5. Separate repository evidence, external evidence, inference and unknowns. Do not copy protected layouts or source code; extract principles and contracts.
6. For UI or architecture choices, produce a short comparison and a recommendation. If the direction materially changes the product, stop at the approval gate before implementation.
7. Return affected paths, contracts, risks, open questions and the cheapest next observation to the manager. Never include secrets, raw customer data or hidden chain-of-thought.
