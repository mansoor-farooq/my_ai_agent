# Feature Documentation

For every material feature or cross-cutting fix, create or update the repository's established feature document location. Keep it compact and source-grounded:

1. intent, scope, non-goals and success condition;
2. entry point to state/service/data/output flow;
3. API, schema, permission, ID and error contracts;
4. loading, empty, denied, retry, partial and unknown-result states;
5. architecture/UI/security decisions and evidence links;
6. verification actually run, limitations and follow-up questions.

Separate Observed facts, Strong inferences and Unverified assumptions. Redact secrets, tokens and customer data. Update only the affected feature section and keep project memory links consistent.
