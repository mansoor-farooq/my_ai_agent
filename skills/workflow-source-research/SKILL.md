# Workflow Source Research

Research the real product/domain before proposing a workflow. Use the available Antigravity `search_web` and `read_url_content` tools; when browser inspection is useful, hand the bounded task to `/browser`.

## Research loop

1. Inspect the target repository and capture real routes, data models, APIs, workflow states and existing constraints.
2. Search Google for the domain process, first-party product documentation, official design systems, API specs and current standards. Search by the actual industry/task, not only by aesthetic adjectives.
3. Open primary sources and verify the relevant claims. Use a second independent source for high-impact or disputed decisions. Record title, direct URL, publisher, access date and the exact claim.
4. Inspect real product examples or public docs for the interaction and data model. Extract principles; do not copy screen layouts or protected assets.
5. Compare alternatives only when they materially affect cost, compliance, reliability, data ownership or user effort. Explain evidence and trade-offs.
6. Save the concise reusable findings to the project research/decision record, not only to chat. Mark evidence, inference and unknowns separately.
7. If search is blocked, report that limitation and do not present remembered patterns as current findings.

|---|---|---|---|---|

Never fabricate a source, feature, benchmark, data field or client workflow.
