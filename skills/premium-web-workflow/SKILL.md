# Premium Web Workflow

Turn the brief into a polished, working result. The current request, existing project conventions, and brand always take precedence.

## Work efficiently

Inspect project instructions and only the files likely to change. Search before reading large files; read narrow relevant sections. Reuse the existing stack and components. Keep a short task list and avoid repeating the brief, plan, or completed findings. Ask only when blocked.

For a large repository, unclear ownership, or long task, also use `efficient-context`. Use native agents only for genuinely independent work, with bounded tasks and non-overlapping files. Otherwise work sequentially.

## Design and build

Use `frontend-design` for visual work when available; otherwise apply these defaults directly:

- For new designs, use a premium light theme with soft neutral surfaces, dark readable text, generous spacing, refined typography, and one brand-appropriate accent.
- Make layout, copy, imagery, and hierarchy specific to the business. Preserve existing branding and obey any requested theme.
- Build responsive, keyboard-accessible interfaces with visible focus, sufficient contrast, and reduced-motion support.

Implement requested interactions end to end. Add loading, empty, success, validation, and error states only where relevant. Do not invent a backend or claim a demo integration is live; clearly state missing credentials or services.

## Verify

Use `webapp-testing` when available. Run the narrow checks that cover changed behavior, then the relevant project build or suite. Inspect desktop and mobile rendering, key interactions, and browser errors. Take screenshots when supported and fix observed problems.

Finish concisely with what changed, where to preview it, checks actually run, and remaining limitations. Ask before public deployment or paid services.
