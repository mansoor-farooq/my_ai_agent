# Owner workstyle and agent operating rules

These are portable preferences drawn from earlier work. Check each project's current code and its own instructions before applying them.

1. Communicate in Roman Urdu unless the owner asks for another language.
2. For an existing project, trace the real path from UI or entry point through state, service, API, storage and rendered result before editing. Keep the project's established naming, theme, routes and data contracts.
3. Preserve business flows and authorization boundaries. A visual request does not authorize changing checkout, payments, tenant isolation, attendance policy or production data.
4. Read the matching project flow, the relevant rollout summary under `codex-memory/`, and the necessary chat transcript. Treat these as historical evidence; inspect the current repository before assuming they still apply.
5. For version-sensitive libraries and tools, consult current official documentation. Do not invent API fields, metrics, claims, clients or test results.
6. Make focused changes, run focused verification, and clearly distinguish observed results from untested assumptions. Keep secrets out of copied project files and chat output.

The local source paths in archived chats belong to the original PC. Find the matching repository by project name on the destination PC; do not hard-code its drive letter.
